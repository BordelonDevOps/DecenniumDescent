# Cursor Batch Execution Guide

The suite is intentionally too large for one monolithic chat. Use Cursor multi-agent work in batches.

## Batch 1 — source and fixture freeze

- Run preflight and static validators.
- Hash sources.
- Build frozen character and monster fixtures.
- Do not reveal enemies until character fixtures are sealed.

## Batch 2 — executable chassis simulations

- Run Packs 07, 08, 11, 12, 13, 14, and 16 through scripts.
- Use agents to inspect anomalies, not to narrate every seed.
- Preserve complete CSV/JSON outputs.

## Batch 3 — tactical agent play

- Run Pack 06 with the 17 class-player files.
- Use the 68 persona profiles for Pack 10.
- Target anomalies found by executable tests.
- Record every die and rules halt.

## Batch 4 — exploit and ceiling stress

- Run Packs 09, 10, and 15.
- Use separate exploit, rules, and statistical auditors.
- Keep Director-only PvP and claimant results in sealed output.

## Batch 5 — full gameplay loop

- Run Packs 02, 11, 12, and 13.
- Require a complete state ledger from charter through Haven settlement.
- Track gross value, net proceeds, and true profit separately.

## Batch 6 — usability and campaign continuity

- Run Packs 05, 14, and 17.
- AI personas can expose friction but cannot prove human fun or comprehension.
- Produce a precise human GM agenda from the findings.

## Batch 7 — release regression

- Run Pack 18.
- Compare untouched V7.1 baseline to any approved patch branch.
- Reject changes that fix one metric by breaking canon, speed, or another gameplay system.

## Context management

- One agent should own no more than one player persona or one audit function.
- Store state in files, not only chat.
- Restart agents between scenario groups when context becomes contaminated.
- Use deterministic source and fixture hashes to prevent accidental drift.
