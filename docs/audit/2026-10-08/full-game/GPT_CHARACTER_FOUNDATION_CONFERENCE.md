# 5. HP / Hit Dice — APPROVE the NEW integration proposal

Operational procedure:

**Character level 1:**  
`max class Hit Die + current CON modifier`, minimum contribution 1.

**Every later character level, including level 1 of a newly entered class:**  
roll that gained class's Hit Die **or** use its rounded-up average:

- d6 → 4
- d8 → 5
- d10 → 6
- d12 → 7

then add current CON modifier, minimum contribution **1**.

Store the base die/fixed value for every attained level and its Hit Die type.

When permanent CON changes, recompute maximum HP as:

> sum over every attained level of `max(1, stored base HP value for that level + current CON modifier)`.

This preserves the source's retroactive CON behavior while making the missing lower floor deterministic.

Do **not** merely add `levels × CON delta` if doing so would bypass a minimum-1 contribution.

### Level-up current HP

Approve the NEW rule:

- increasing maximum HP does **not** heal current HP;
- if maximum HP decreases below current HP, clamp current HP to the new maximum;
- level-up never raises a 0-HP character, resurrects Dead, ends Wounds, or acts as a rest.

Level-up does not refill RP, RC, BG, Momentum, class pools, Hit Dice, item charges or per-rest uses unless an exact feature expressly triggers from gaining a level.

Track Hit Dice by die size for actual short-rest spending.

# 7. Multiclass entry — APPROVE with one generalized chassis rule

### Prerequisites

When taking a **new Base class**, require the character currently to satisfy the multiclass prerequisites for:

- every Base class already possessed; and
- the new Base class.

This is the approved precise interpretation of “current class and new class.”

A later temporary or permanent score reduction does **not** remove already-earned class levels/features. It can, however, prevent entry into another new class until the prerequisites are again satisfied.

### First class versus later classes

Only the character's **first character class** grants:

- full starting saving-throw proficiencies;
- full starting class proficiency chassis;
- starting equipment/package or starting wealth.

A later newly entered class grants exactly its **Multiclassing Proficiencies** table row.

No additional saving throws, background, wealth or equipment package.

The class's actual level-1 engine/features and schedule still occur.

### Paladin Martial Proficiency

Approve the proposal and generalize it:

> A level-1 card whose sole mechanical function is to restate that class's starting armor/weapon proficiency chassis is treated as presentation of the starting chassis when entering that class after character level 1. It cannot bypass the Multiclassing Proficiencies table.

Thus multiclass Paladin does **not** recover heavy armor solely through `Martial Proficiency`.

If a level-1 feature contains an independent mechanic beyond restated chassis proficiencies, that independent mechanic still applies.

### Duplicate shared chassis features

- Use one applicable AC formula at a time; never add formulas together.
- Equivalent Extra Attack sources use the **largest actual attack count**, not their sum.
- Generic duplicate Channel Divinity-style labels do not automatically create duplicate pools/uses.
- Distinct named operational class mechanics remain distinct unless an exact rule says they are equivalent.
- Genuine paid techniques retain their own Action/costs and remain subject to universal action limits.

# 8. Multiclass RP — APPROVE

Keep the existing formula:

> **highest-ranked eligible Weave class's pool at its own class level + ceil(25% of one secondary eligible Weave class's pool at its own class level).**

Never sum class levels before reading pool tables.

Tier order:

1. **Full:** Cleric, Druid, Mage, Wizard
2. **Half:** Paladin, Ranger
3. **Hybrid:** Bard, Shaman, Mirrorsage, Crimson Agent
4. **Minor:** Dragoon, Monk, Thief, Tinker
5. **Excluded:** Oracle, Soldier, Warrior

Within a tier, order candidates by:

1. higher class level;
2. higher actual pool at that class level;
3. **earlier class acquisition order** as final deterministic tie-break.

Use that ordering to select both primary and secondary.

This is state-derived, not player-selected separately for every cast.

Tertiary/later caster classes contribute **0 additional maximum RP**, but retain their legal class cards/spells/access.

All actual RP costs from spells or class techniques draw from this **one merged character RP pool** unless an exact source gives a different resource.

RC, BG, Ki, Momentum, Conviction, Lay on Hands and other named resources remain separate.

On maximum-RP change:

- raising max does not refill current RP;
- lowering max clamps current RP to new max.

No class entry or pool-primary change is a rest.

# 9. Multiclass Dissonance / Refrain / concentration — APPROVE, using **per-casting-class threshold**

Use **one character-wide Dissonance value** and **one character-wide Refrain spell-history stream**.

Do **not** maintain one copy per class.

For each ordinary spell:

1. declare its casting class;
2. use that class's actual spell rank/access;
3. use that class's actual casting modifier for its attack/DC;
4. use that same casting modifier when evaluating the Dissonance threshold for **that cast**.

So:

> `limit = max(4, 2 + PB + max(0, that cast's actual casting-class modifier))`

I prefer this over a fixed primary-class threshold. It prevents a high primary stat from silently improving secondary-class spellcasting strain, while preserving each class's own spellcasting competence. The Dissonance number is still shared, so switching classes does **not** reset accumulated strain.

Same canonical spell identity cast through another class still advances the same Refrain repetition history.

Class-specific cadence reductions/vents apply only when their exact ownership/trigger conditions are satisfied.

Idle-turn Dissonance decay and Grounding occur **once per character turn**, never once per class.

### Recovery

Generic Retune is once per completed eligible short rest for the character, not once per class. Use the current **primary RP class** determined by the RP ordering above for its casting modifier.

Likewise the optional once/day meditation uses that primary class's casting modifier.

Long rest restores the merged RP pool and clears Dissonance under the already-reviewed rule.

Oracle Revelations use RC and do not generate ordinary Weave Dissonance unless an exact Oracle rule says otherwise. Using Oracle abilities does not clear or partition existing Dissonance/Refrain history from other classes.

### Concentration

One ordinary character-wide concentration slot across classes, subject only to exact reviewed exceptions such as Spell Tether/Tethered Cast/Crimson Harmony.

No generic Overcast is reintroduced.
