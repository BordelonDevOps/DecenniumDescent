### How to read implementation status

**TECHNICAL** means bounded infrastructure is implemented/tested. **PROVISIONAL** means source-bound procedures behind TEST_ONLY guards. **FIXTURE** means synthetic proof only. **NOT PORTED** means no corresponding C# gameplay implementation exists. **PARTIAL TECHNICAL** and **DEFERRED PRESENTATION** retain verification/product work without implying a complete rules engine.

Sources link to immutable GitHub files; section/record names narrow their scope. Dependencies and concrete acceptance checks are retained per work item in the JSON map. Connected-loop dependencies require concrete source-bound minimum slices, not just a mode switch; completing that narrow loop is distinct from completing every catalog payload.

### Decisions and gaps that must stay visible

1. **Direct exploration:** running, jump/landing, interaction reach, follow behavior and mode transitions need precise engine policies. Existing turn movement and provisional5-ft geometry do not automatically decide direct-control movement.
2. **Digging and farming:** mining specifies finite exposed-node extraction, not tunnel excavation. No complete ordinary farming procedure was located in the bounded mechanics/expedition review; this is a source-discovery limit, not proof that no archive contains one.
3. **Timing:** keep authored regular-turn/reaction/recharge rules, absolute deadlines and EX58 work time; settle any digital conversion ambiguity without double-counting intervals or worker effort.
4. **Research and fishing are not blank slates:** existing-formula research, fishing commitment/cancellation, and the unattended Trap have concrete procedures. Schema37 implements one bounded physical Trap/retrieval witness; broader stock, assembly, equipment, methods and handover still need C# state and source binding. Only unsupported extensions need new decisions.
5. **Approvals differ by domain and scope:** new DD11 canon promotion, reviewed authored recipes, incomplete feat payloads and an unadopted environment draft cannot share one blanket ready/not-ready label. Preserve exact qualifications and reject unsupported operations.
