# Pure assessment extraction findings

Static source review at runtime baseline `748c6debca56fd7d1a8b89e8b2ad7de12e8da5eb`, unchanged through design commit `c807ada65`. This is a concrete extraction worklist, not a completed transitive purity proof or permission to implement. Existing copied-state queries do not mutate the live campaign. The new contract is stricter: no command resolution, choice settlement, historical replay, RNG or simulated resource transfer to answer a read.

## Shared guard order

`TestOnlySharedWorldPolicy.ResolveCore`, lines 863–1035, contains ordered early branches, not one common preflight followed by interchangeable family handlers. In order it checks or dispatches: world actor; Ferry Dash and off-calendar seal work; long rest and active-rest conflict; Sanctuary; Guidance and physical contamination; casting/repertoire; Cleric short-rest denial; Consecration/Invocation/Rite/Presence; noncasting short rest and active-rest conflict; decay/wound treatment and occupied participants; ordinary search/hide conflicts and procedures; retreat; recovery choice and rest/care conflicts; Haven appraisal/episode close; reinforcement/stabilization; charter/plan/bill/sale/meal; meal-serving restrictions; ordinary observation; specimen handling; off-calendar work; advancement; content/recipe watch and manufacturing choice; seal; portable; mining; preservation; manufacturing/trap/cache/formula; finally tactical or ordinary management.

That sequence contains branch-specific early returns. A later gate must not be hoisted ahead of a family that previously returned earlier. The new native assessment design must share these ordered entry conditions with authoritative execution. It must not copy a selection of conditions into a host switch or call the whole resolver merely to obtain the ordering. Host malformed/conflict/stale/known-target checks, core current-authority preflight, native family admission and result disclosure remain separate layers.

## Verified passage proposal for review

`VerifiedSharedWorldCheckpoint` already owns private immutable `PlanningPassage`, original `VerifiedSimulationOrigin`, revision/fingerprint and canonical predecessor bytes. `VerifyOwner` (166–171) checks the actual owner/policy/wire/revision; `ResolveNext` (153–164) checks canonical bytes before using the passage in authoritative execution. The passage's Covers/StartThrough (107–113) are read-only predicates. Every one of the 24 session factories selects verified construction.

Propose an optional pure assessment capability on the existing checkpoint, called only by its owning Simulation after the same current authority/receipt preflight. It receives the actual origin and detached current snapshot, verifies owner and canonical bytes through an explicitly audited pure comparison mechanism, and delegates to the native pure assessor with its private passage. It returns immutable assessment facts and never calls ResolveNext, VerifyNext, ReplayReceipt, Initial, AdvanceTo or a resolver. No proof or grant is supplied by JSON, no gameplay state/schema changes, and no new passage is invented. Restore continues full existing authenticity validation before constructing the owning checkpoint. A missing or mismatched checkpoint must reject safely, never fall back to replay during a read.

**Additional unresolved purity dependency found by independent review:** the existing `SnapshotCodec.Encode` cannot be used as that pure comparison mechanism. `Runtime/Persistence/SnapshotCodec.cs` 17–19 calls Validation.Snapshot; Simulation.cs 1208/1213 reach SpellCastingProfile.Validate and FerryWraithProfile.Validate. SpellCastingValidation.cs 59/120/156 and FerryWraithRecords.cs 305 reconstruct retained dice with DiceStream.Draw. This leaves live state unchanged but violates the stricter no-RNG read contract. The design must either extract/audit a pure canonical-byte serialization/comparison path while retaining identical bytes and original execution/restore validation, or obtain explicit GPT agreement on another equally bound owning-snapshot proof. No unchecked encoding escape hatch, relaxed byte check or implicit historical-RNG exception is accepted here.

This is a proposal to resolve an identified read-path dependency. Exact interface, failure projection and applicability remain open for actual GPT review; it does not authorize code.

## Current eligibility versus later consequences

An assessment may describe currently known costs and conditional consequences without resolving later randomness, deadlines or interruptions. It must not promise an entire future interval succeeds merely because present prerequisites pass. Define the exact condition/continuation fields for timed operations in the per-operation matrix. Actual detailed submission captures the authoritative result of the real attempt; it never substitutes a prior assessment for the actual execution response.

All other family guards, source clauses, parameter domains and witnesses remain subject to HC-D2–D8. This worklist is deliberately not labelled an exhaustive audit.
