## Persistence and compatibility boundary

The new envelope is wire schema115 over the retained underlying shared schema. `Snapshot.Copy` retains immutable Consecration records. `SnapshotCodec` emits/reads the extra marker and payload only for the new composition; it requires exact end-of-stream and validated envelope identity. `ClericSettlementCodec` adds the real pre-Radiance value only in115 and passes it directly to the new constructor. The old decode branch supplies the original base HP, retaining old Radiance arithmetic. Old profiles cannot contain an enlarged intermediate HP without the explicit new composition.

The new codec checks exact source/area/roster strings, counts, canonical quantity/time constructors, enum values, duplicate identities and derived attack fields. Historical zone creation binds command center/owner/revision, actual source grant, paid RP and original deadline. Ground binds the corresponding paid Rite and zone. The public restore path still reconstructs canonical history and compares encoded state; the new profile is explicitly included in `VerifiedExpeditionWireSchema`. It does not reuse an accepted114 verification origin or relax origin ownership.

These layers have different jobs. Structural validation catches many malformed or unmatched records. Historical payment/position/perception/LOS, missing or extra rider application, and faithful command replay additionally depend on the existing canonical reconstruction and equality checks. A structurally encodable modified snapshot is not thereby a supported restored save. No fixture state may be adopted by relabeling its profile or checksum.

For95–114, inspected branches continue to use their existing fingerprint, wire discriminator and codec fields; new attack and healing helpers return zero/no-op when Consecration is absent, and new observations return empty. The extra RP event sequence is empty. The private accessors avoid adding properties to old automatic Command/Radiance serialization. Existing enum values were not renumbered. This is a static compatibility assessment, not measured old-byte, old-view or continuation equality. Authentic supported-save checks and old console/public-view comparisons remain required evidence. No mixed-version assembly ABI compatibility is asserted.
