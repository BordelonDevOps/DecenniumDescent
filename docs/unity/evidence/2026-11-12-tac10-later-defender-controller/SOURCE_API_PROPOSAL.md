## Existing code and scope

The package search found existing scoped observation and command primitives. `Simulation.Capture` is for trusted simulation and persistence. `ObserveExplorationSearch` and `ObserveExplorationHide` show the authority-checked projection pattern. `ObservationRules.KnownLocations`, `CanSee` and `ObservationGeometry.LineOfEffectClear` provide distinct spatial facts. `Simulation.QueryCommand` and `Execute` share command and authority preflight. General `DiscoverCommands` produces authoritative query results including denial reasons and candidate destinations, so the selector receives neither that feed nor a handle to call it. The current `FinishLaterFight` test helper captures unrestricted state and uses `LaterHost` to script both sides. We found no reusable decision selector in the C# package. `SharedLaterEncounter` already registers the defender body, initiative and held Club. These are the inputs for this controller.

## Observation and authority

The trusted host binds the controller to the existing later defender and gives it a fixed principal, control of that defender and inventory permission for the defender's own Club owner. It has no clock or world grant and cannot act for the hero. It is callable only while the actual later encounter is active in the selected TEST_ONLY connected profile. Keep the versioned controller choice in caller configuration for save/restore. Record only normal commands and existing receipts in game state.

The trusted adapter constructs a detached immutable decision view. Own facts are position, represented ability to act, current stance for this turn, Action availability, remaining movement or permission, availability of the bound held Club, and Reaction eligibility for an actual offer. The only opposing records in the view are current directly seen, admitted hostiles with their current visible coordinates and an independently computed line-of-effect flag. A remembered location remains distinct from sight and does not drive this first policy. No opposing HP or injury, defense, conditions, inventory, resources, inaccessible actor IDs, raw turn schedule, future RNG, history, or authoritative diagnostics enter the view. Known walkable adjacent terrain and directly seen blockers can inform movement. Current unseen occupancy, traps and hidden actors cannot inform destination ranking or give the selector an alternative move. A pending decision belonging to someone else is exposed only as waiting.

The selector is a pure function over the view. It returns one intent or a waiting result. It has no `Simulation`, `Snapshot`, raw query function, results feedback or ability to submit commands. The dispatcher materializes the intent at the observed revision, uses a stable controller command ID derived from the current revision and intent, and submits through the existing host with the defender-only grant. The caller receives an outcome sufficient to hand control back, without private query or resolver payloads. Repeated polling at a blocked revision must yield control to the caller.

## Decision policy

1. Respect existing decision precedence. Use the current resolver's priority, including outer recovery and calendar gates, ordered interrupts, then the current regular actor. Only answer an ordinary opportunity choice naming this defender as the active responder. Accept with the bound Club only against the currently seen provoking actor when the defender is eligible and can use the Club. Otherwise decline through the existing response. Use the ordinary damage outcome and keep existing Press state. For any other pending response, return waiting with no action, including defender-owned choices outside the supported policy. If a response becomes invalid, stop and reassess at the next explicit caller opportunity.
2. On its regular turn, select Guarded once when permitted. An unaware or defeated defender may submit the existing legal turn end where supported. No special condition removal, stance bypass or free turn advancement is introduced.
3. With an available Action and Club, prefer an in-reach directly seen hostile with clear line of effect, ordered by existing tactical distance and then ordinal actor ID. Submit ordinary Club attack with the existing keep-Press instruction and no knockout declaration. If no such target is in reach, choose the nearest directly seen hostile by the same order and one adjacent known walkable anchor that strictly reduces the existing cell distance. Exclude directly seen blockers. Rank by resulting distance, then ascending X and Y. Use the existing absolute-coordinate TacticalStep payload. If no target, no permitted approach, or the Action is spent, end the regular turn normally.
4. Make at most one primary attempt per decision call. The trusted dispatcher may try one fixed fallback when the primary intent cannot be admitted at the same revision. For a normal attack or step the fallback is ordinary turn end. For a still-pending owned opportunity that could not legally accept, it is a decline. Neither fallback probes another target or cell or uses a private rejection category. Yield if the fallback cannot commit. Recompute from the new projected state only after actual resolver consequences. The defender never closes the expedition encounter or takes the player's next action.

## Shared legality and persistence

Reuse the query and execution admission paths. Tactical movement already shares `StepFailure`; the regular turn-end query currently runs the detached resolver, which can reach later due events. Do not run the resolver to preview future rolls for selection. Where a bounded stance, attack, opportunity or end-turn admission assessment is needed, extract the necessary pre-roll guard from the current resolver and reuse it there. Keep authoritative settlement, RNG, mutation, full validation and due-event processing in execution. Keep existing human queries and command behavior intact. The dispatcher checks only the selected intent and its fixed fallback. Generic waiting and ordinary committed outcomes suffice. An actual move changing or leaving one's own position is an action consequence. Rejected alternate movements and occupancy-specific messages must never reach the selector.

A submitted action is a normal authoritative command. Use the same command ID for a repeat delivery at the same revision, a fresh view after a commit, and existing stale-revision and duplicate handling. The selector has no independent RNG, timer, mutable tactical memory or receipt ledger. Restore authentic supported saves through the existing validators, supply the same explicitly selected controller, and compare the next intent and command and final bytes. A recorded command history must replay without invoking the selector.
