## Reference path and trust

`Simulation` validates the selected snapshot and scope on construction. Each accepted command then checks current authority, receipt identity, revision and capacity, resolves a detached candidate, appends the actual receipt and validates the candidate before adopting it. `TestOnlySharedWorldPolicy.ValidateState` checks the profile and domain state, reconstructs the complete prefix from `Initial` using parsed command receipts, and compares the full canonical persistence bytes. Each command repeats all prior resolution. The accepted implementation is the equivalence reference.

External snapshots, restored files, recovered backups, different selected profiles and independent Simulation instances require the current complete validation. A file carries no live trust or cached proof. The host must select the correct content and execution profile. A valid-looking revision or digest from outside the live session confers no trust. Save and backup recovery continue to use the existing codec and store.

The live session already owns a validated predecessor. The new path can use that fact only through a sealed per-instance checkpoint established after complete validation. A proposed command and its candidate remain untrusted until they pass the normal transaction and the independent transition comparison. The public capture stays detached.

## Proposed correction

Add an explicit opt-in for the selected TEST_ONLY wire95 session. Preserve the current constructor/default validation and all other policy/profile behavior. An optional policy capability gives the trusted `Simulation` instance a private checkpoint after the usual full constructor validation. The checkpoint contains canonical predecessor bytes from its verified state, exact policy/profile identity and revision. Only the Simulation owns the checkpoint handle. Callers cannot inject a checkpoint, restore it from a file, share it between instances, or obtain it through Capture.

For an authorized new command, retain the same detached resolver, receipt and structural validation. Reuse all selected policy/profile domain guards. Verify that the private live predecessor matches its sealed canonical bytes. From a detached decode of those bytes, replay exactly the one proposed receipt using the existing receipt parser and resolver. Compare the full canonical candidate bytes with the independently replayed successor. Commit the successor and advance the sealed checkpoint together after equality. Leave both predecessor and checkpoint intact on denial, invalid result, stale or conflicting delivery, and duplicate outcomes. The existing commit and load paths still provide the failure categories.

The checkpoint makes prefix replay incremental. It does not skip structural validation, active profile constraints or full canonical result comparison. Retaining the verified prefix is justified by induction: external construction proves the entire prefix, and each later command proves the exact successor through the same replay resolver. The canonical bytes isolate the reference transition from mutable candidate aliases. Document and verify that resolver behavior has no policy-owned history side effect required for replay equivalence. If an observed invariant defeats that premise, keep the full path for that policy until it is resolved. Keep assembly dependencies in their existing direction. The Core adapter should store an opaque capability while the LabModel continues to own its existing Persistence dependency and canonical comparison.

No runtime validation change is in the proposal commit. A later implementation should keep the full reference mode executable and run equivalent inputs in separately configured instances. Performance evidence must also use the actual public command path.

## Acceptance before relying on the faster path

- Establish exact parity of outcomes, relevant denials, receipts, revision, clock, RNG, authoritative resources and canonical bytes after each command through the accepted connected history. Cover an actual pending opportunity, work milestone, returned or consumed resources, encounter closure and ordinary continuation. Start a fresh reference and candidate from authentic compatible snapshots and continue through the same commands. Replay the resulting history with the original full path.
- Preserve wrong actor and inventory-owner denials, invalid payload, stale and duplicate behavior, capacity and failing transactions. Exercise a rejected command between legal commands and a recoverable failed commit so the next comparison uses the same predecessor. Compare equivalent invalid external files, incompatible profile and scope, malformed receipt/provenance, codec/save recovery, and canonical replay failures. External restoration must always use full validation before any new checkpoint exists.
- Verify independent sessions with matching revisions cannot exchange checkpoints. Verify caller mutation of a captured copy cannot affect the trusted prefix or the live result. Detect an internally inconsistent checkpoint and fail closed. Keep previous binary formats and original accepted bytes restorable without a migration.
- Measure isolated repeated timings at the same checkpoints with unchanged hardware and assembly bindings. For the selected profile and measured history lengths, propose p95 at or below 150 ms for routine command execution and 350 ms for the measured stabilization milestone. The existing milestone resolver alone reached 114 ms in the baseline, so allow for the authoritative resolution and its independent verification. Report worst samples and separately report actual save/restore time. Keep the complete restore verification even if startup is slower than live actions. These are proposed turn-based session budgets for review, not a frame-rate requirement or a promise on other hardware.
- Retain focused equivalence, exact source and assembly bindings, compilation and static evidence, authentic compatibility checks and a completed exact regression. After P1 acceptance, use the new path through the controllable session and show its actual end-to-end latency and restore continuation at the public input surface.
