Proposed adapter operations are declared bounds, supported anchor, destination terrain, static corner facts and channel queries. ## 4. G-SUPPORT-01: preserve bounded anchor and channel semantics

The existing technical representation rejects actor/object/traversal anchors on a cell blocking **any** sight/effect/movement channel. Preserve this explicit support limitation. A sight-only or effect-only blocker does not thereby become universally impassable material under game rules; this profile has no separately authored support surface inside such a cell. Commands may reject unsupported anchor placement, while ray evaluation still uses only the requested channel. Do not silently change `SupportsAnchorAt` to only inspect `BlocksMovement`, including for inherited(2,1).

Use existing exact ray/supercover algorithms and source-conditioned observation. Geometric sight alone does not grant perception to Blinded/Unaware actors or reveal Hidden/Invisible actors. Effect checks do not bypass targeting, range, cover or source-area-origin requirements. No new half/three-quarter cover generator is inferred from these binary cells. Existing cover procedures remain independently sourced.

Tactical adjacent movement keeps equal orthogonal/diagonal5ft cost before terrain. Both orthogonal side anchors unsupported blocks a diagonal; one unsupported side alone does not. In this bounded support model (6,0)->(7,1) is a blocked two-side example through(7,0)/(6,1). Preserve old corner/channel algorithms rather than generalizing this to 3D surfaces or doorways. Ordinary `BeginWorldStep` remains cardinal; map expansion does not authorize diagonal exploration.
